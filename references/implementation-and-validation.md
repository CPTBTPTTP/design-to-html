# 实现与视觉验收

## 实现顺序

按以下顺序工作，避免局部微调遮蔽结构问题：

1. 页面容器、栅格、主要区块和滚动结构；
2. 全局字体、文字角色、行高和内容密度；
3. 卡片、按钮、表单、图标等共享组件；
4. 图片、插画、静态装饰与裁图；
5. 阴影、边框、渐变、微间距和状态细节。

实现必须保留语义化 DOM、可替换数据和可维护路由。显式重置原生表单控件，避免浏览器默认样式成为未登记的视觉差异。

## 校准页

批量开发前选一张涵盖典型容器、标题、卡片、图片和主按钮的代表页。以 P0 视口截图并修复：

- 画布换算和页面容器；
- 字体是否真实加载、字重/行高/密度是否正确；
- Token 和组件是否足以覆盖重复结构；
- 静态素材裁切及边缘是否正确；
- 截图脚本的实际 CSS 视口、DPR 与等待条件。

只有上述结果可复现，才能将组件推广到其余页面。

## 对比与差异清单

每次验收使用同一 P0 条件：同画布、DPR、状态、数据、滚动位置和字体。长页面至少设置首屏、核心区、页尾三个锚点；短页面可由 T2 定义等价锚点。

差异清单应以影响排序，并标注：位置、类别、金样表现、当前表现、修复方案、受限原因和复验结果。评分用于辅助优先级，而不是替代证据；没有对比图或明确观察记录时，不得声称达到高保真阈值。

当一项偏差源自共享 Token、字体映射或截图条件，修复源头并回归所有引用页面；不要只在单页末尾追加覆盖样式。
